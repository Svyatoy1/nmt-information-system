# NMT Information System

Навчальна інформаційна система для роботи з даними підготовки до НМТ, розроблена в межах дисципліни **«Інформаційні системи»**.

Метою проєкту є не створення повноцінного кінцевого продукту, а побудова базового каркасу інформаційної системи та дослідження взаємодії між її компонентами: сервісом обробки запитів, базою даних, системою моніторингу та Docker-контейнерами.

## Опис системи

Система працює з предметами та тестовими питаннями для підготовки до НМТ.

На поточному етапі реалізовано:

- зберігання предметів НМТ;
- зберігання тестових питань;
- отримання списку питань;
- отримання випадкового питання;
- додавання нових питань;
- перевірку доступності сервісу та бази даних;
- збір метрик роботи API;
- автоматизовану перевірку функціональності;
- генерацію тестового HTTP-трафіку;
- контейнеризований запуск компонентів системи.

## Архітектура

```text
                User / Test scripts
                        |
                        | HTTP
                        v
                     FastAPI
                    /       \
                   /         \
                  v           v
            PostgreSQL      /metrics
                                |
                                v
                            Prometheus
```

FastAPI є основним сервісом системи.

Він:

- приймає HTTP-запити;
- виконує операції з PostgreSQL;
- перевіряє вхідні дані;
- формує метрики;
- надає endpoint `/metrics` для Prometheus.

Prometheus періодично отримує метрики FastAPI та зберігає їх у власному Time Series Storage.

## База даних

У системі використовується PostgreSQL.

Основні сутності:

### subjects

Містить предмети НМТ.

Приклади:

- Математика
- Українська мова
- Історія України

### questions

Містить тестові питання.

Для кожного питання зберігаються:

- ідентифікатор;
- предмет;
- текст питання;
- правильна відповідь;
- рівень складності.

Між таблицями `subjects` та `questions` реалізовано зв'язок **один-до-багатьох**.

```text
subjects
   |
   | 1
   |
   | N
   v
questions
```

## API

FastAPI працює на:

```text
http://localhost:8000
```

### Основні endpoint-и

```text
GET  /
```

Перевірка запуску API.

```text
GET /health
```

Перевірка стану сервісу та підключення до PostgreSQL.

Приклад відповіді:

```json
{
  "status": "healthy",
  "database": "connected"
}
```

```text
GET /questions
```

Повертає список усіх питань.

```text
GET /questions/random
```

Повертає випадкове питання з бази даних.

```text
POST /questions
```

Створює нове питання.

Приклад:

```json
{
  "subject_id": 1,
  "question_text": "Чому дорівнює квадрат числа 5?",
  "correct_answer": "25",
  "difficulty": "easy"
}
```

```text
GET /metrics
```

Надає метрики у форматі Prometheus.

## Swagger

FastAPI автоматично формує документацію API.

Після запуску системи Swagger доступний за адресою:

```text
http://localhost:8000/docs
```

Через Swagger можна вручну перевірити GET- та POST-запити.

## Моніторинг

Для збору метрик використовується Prometheus.

Prometheus доступний за адресою:

```text
http://localhost:9090
```

FastAPI експортує метрики через:

```text
http://app:8000/metrics
```

Prometheus автоматично виконує їх збір через заданий інтервал часу.

### Реалізовані метрики

```text
nmt_question_requests_total
```

Кількість операцій отримання питань.

```text
nmt_questions_created_total
```

Кількість успішно створених питань.

```text
nmt_database_errors_total
```

Кількість помилок під час роботи з базою даних.

Наприклад, у Prometheus можна виконати:

```promql
nmt_question_requests_total
```

або:

```promql
nmt_questions_created_total
```

Для перегляду частоти запитів:

```promql
rate(nmt_question_requests_total[1m])
```

На поточному етапі окремі exporters для PostgreSQL не використовуються. Метрики формуються безпосередньо FastAPI-сервісом.

## Docker

Усі основні компоненти запускаються через Docker Compose.

У системі використовуються три контейнери:

```text
app
db
prometheus
```

де:

- `app` — FastAPI;
- `db` — PostgreSQL;
- `prometheus` — система збору метрик.

Контейнери працюють у спільній Docker-мережі.

Тому FastAPI підключається до PostgreSQL через:

```text
db:5432
```

а Prometheus отримує метрики через:

```text
app:8000
```

## Запуск

Для запуску системи:

```bash
docker compose up --build
```

Після запуску:

```text
FastAPI:
http://localhost:8000

Swagger:
http://localhost:8000/docs

Health check:
http://localhost:8000/health

Prometheus:
http://localhost:9090
```

## Автоматизована перевірка

Для автоматизації тестування створено два Python-скрипти.

### demo_requests.py

Запуск:

```bash
python scripts/demo_requests.py
```

Скрипт:

1. перевіряє `/health`;
2. отримує список питань;
3. отримує декілька випадкових питань;
4. створює нове питання;
5. повторно отримує список;
6. перевіряє, що кількість записів у PostgreSQL змінилася.

Це дозволяє автоматично перевірити основну функціональність системи.

### generate_traffic.py

Запуск:

```bash
python scripts/generate_traffic.py
```

Скрипт генерує серію HTTP-запитів:

```text
20 × GET /questions/random
5 × GET /questions
3 × POST /questions
```

Його призначення — імітація активності користувачів та створення даних для перевірки Prometheus.

## Відповідність умовам навчального проєкту

В умовах лабораторної роботи передбачено створення інформаційної системи, яка працює з базою даних, збирає метрики та використовує засоби моніторингу.

### Реалізовано

| Вимога | Реалізація |
|---|---|
| Запуск СУБД у Docker | PostgreSQL працює у Docker-контейнері |
| Програмний доступ до БД | Python + FastAPI + SQLAlchemy |
| Отримання даних із БД | GET `/questions`, GET `/questions/random` |
| Актуалізація даних | POST `/questions` |
| Збір метрик | Prometheus |
| Time Series Storage | Вбудоване сховище Prometheus |
| Контейнеризація | Docker + Docker Compose |
| Моніторинг операцій | Власні метрики FastAPI |
| Автоматизація запитів | `demo_requests.py`, `generate_traffic.py` |

### Можливе подальше розширення

В умовах дисципліни також передбачені інструменти, які можуть бути додані на наступних етапах:

- **Grafana** — візуалізація метрик Prometheus;
- **Grafana Loki** — централізований збір та аналіз логів;
- **Grafana Tempo** — дослідження трасування запитів;
- **сервер авторизації** — обмеження доступу до системи;
- **RabbitMQ або Apache Kafka** — обмін повідомленнями між сервісами.

Використання брокера повідомлень не є обов'язковим відповідно до умов роботи, тому в поточній версії взаємодія компонентів реалізована через HTTP та програмні методи.

## Поточний результат

На поточному етапі реалізовано працездатний базовий каркас інформаційної системи.

Система демонструє повний цикл:

```text
HTTP request
     |
     v
FastAPI
     |
     v
PostgreSQL
```

та паралельно:

```text
FastAPI
   |
   | metrics
   v
Prometheus
```

Таким чином проєкт демонструє:

- роботу з реляційною базою даних;
- створення REST API;
- взаємодію між програмним сервісом та СУБД;
- контейнеризацію компонентів;
- перевірку працездатності системи;
- збір і аналіз метрик;
- автоматизацію функціонального тестування;
- можливість подальшого масштабування інформаційної системи.

          |              |              |
          v              v              v
   Questions Service  Auth Service  Results Service
          |              |              |
          +--------------+--------------+
                         |
                         v
                     PostgreSQL

                     Prometheus
                         |
                         v
                      Grafana

Logs  -> Grafana Loki

Також предметну частину можна розширити:

- реєстрацією та авторизацією користувачів;
- вибором предмета НМТ;
- формуванням тестів;
- проходженням тестування;
- автоматичною перевіркою відповідей;
- збереженням результатів;
- статистикою проходження тестів.
